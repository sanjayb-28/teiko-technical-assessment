# Teiko Technical Assessment

Analysis of immune-cell population data using Python, SQLite, and an interactive Streamlit dashboard.

## Run the project

Python 3.10 or newer is required. From the repository root, run:

```bash
make setup
make pipeline
make dashboard
```

`make pipeline` rebuilds the database and every required output without manual steps. After starting the server, [open the dashboard](http://localhost:8501).

### GitHub Codespaces

Create a Codespace from the repository, wait for dependency installation to finish, then run:

```bash
make pipeline
make dashboard
```

Open the forwarded port `8501` when prompted. The included development-container configuration uses Python 3.12 and installs the project dependencies during Codespace creation.

## Project structure

| Path | Purpose |
| --- | --- |
| `schema.sql` | Relational schema, constraints, indexes, and frequency view |
| `load_data.py` | Validates the source CSV and rebuilds `cell_counts.db` |
| `analysis.py` | Produces sample frequencies, statistical results, and the static boxplot |
| `subset_analysis.py` | Queries the requested baseline subset and summary measures |
| `dashboard.py` | Presents the generated results in an interactive Streamlit dashboard |
| `outputs/` | Reproducible tables and plot generated by the pipeline |
| `tests/` | Data-loading, analysis, subset, and dashboard checks |

Each program has one focused responsibility and can be run directly. The Makefile combines them in dependency order for reproducible grading.

## Database design

| Table | Purpose |
| --- | --- |
| `projects` | One record per clinical project |
| `subjects` | Subject attributes and project membership |
| `samples` | Biological sample type and treatment timepoint |
| `cell_populations` | Reference list of immune-cell populations |
| `cell_counts` | One count per sample and cell population |

The normalized design separates project, subject, sample, and measurement data. Foreign keys preserve relationships, unique constraints prevent duplicate source identifiers, and checks reject invalid ages, timepoints, and cell counts. Indexes cover the fields used by the analytical filters.

Cell measurements are stored in long form, so populations can be added without changing the sample schema. This supports hundreds of projects and thousands of samples while keeping population-level queries consistent. SQLite is appropriate for this self-contained analysis; the same relational model can move to a server database if concurrent writes or substantially larger workloads are required.

The `sample_cell_frequencies` view calculates the sample total and relative frequency used by the analysis and dashboard. It keeps this business rule in one query rather than duplicating it across outputs.

## Outputs and findings

The pipeline creates:

- `cell_counts.db`
- `outputs/cell_frequencies.csv`
- `outputs/statistical_results.csv`
- `outputs/responder_boxplots.png`
- `outputs/baseline_samples.csv`
- `outputs/subset_summary.csv`

For the responder comparison, each subject's PBMC percentages are averaged across days 0, 7, and 14 before a two-sided Welch t-test is run for each population. Benjamini-Hochberg correction controls the false discovery rate across the five tests.

CD4 T cells have a significant difference between responders and non-responders (raw `p = 0.0045`, adjusted `p = 0.0226`). The other four populations do not meet the adjusted `p < 0.05` threshold. This is an association with response, not a trained or validated predictive model.

The requested baseline subset contains 656 melanoma PBMC samples at day 0 from subjects treated with miraclib: 384 from `prj1` and 272 from `prj3`. It includes 331 responder and 325 non-responder subjects, with 312 female and 344 male subjects. Across melanoma male responders at day 0, including all sample and treatment types, the average B-cell count is `10206.15`.

## Tests

After `make setup` and `make pipeline`, run:

```bash
make test
```

The tests verify source loading, database integrity, deterministic outputs, analysis criteria, statistical results, subset calculations, and dashboard rendering.

GitHub Actions runs the setup, pipeline, and test commands for every push and pull request.
