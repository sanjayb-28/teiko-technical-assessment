# Working Guidelines

## Do

- Keep changes small, focused, and easy to review.
- Prefer clear, direct code over unnecessary abstractions.
- Preserve source data and make generated results reproducible.
- Add comments only when they explain non-obvious reasoning.
- Run relevant checks before committing or merging changes.
- Use concise, professional commit messages and documentation.

## Don't

- Do not push or create remote resources without explicit approval.
- Do not commit secrets, credentials, caches, environments, or local planning notes.
- Do not modify source data to make an analysis pass.
- Do not add unnecessary comments, generated-by headers, or co-author trailers.
- Do not rewrite published history or use destructive Git commands without approval.
- Do not claim results that have not been reproduced from the source data.
